Expanding the Unikraft Software Support Ecosystem

Unikraft turns an application into a tiny, single-purpose virtual machine called a unikernel. It runs software through library ports: build recipes that fetch an upstream project, patch it so it works without a normal OS, and compile it into the image. Some of the most important ports had fallen years behind upstream, and the C++/LLVM ports no longer built with any recent compiler. I brought them up to current releases and tested every port by building and booting it on x86 and arm64.

SimpleHypervisor in progress

A type-2 hypervisor built directly on the Linux KVM API, with no QEMU involved. It boots an unmodified Linux kernel to an interactive BusyBox shell in about one second.

  • Implements the x86 Linux boot protocol by hand: loads the bzImage and initramfs, fills in boot_params, the e820 memory map and the kernel command line
  • Builds a GDT and puts the vCPU straight into 32-bit protected mode
  • Emulates a 16550 UART with interrupt-driven I/O on IRQ 4, with a separate input thread so the guest console is interactive

Bare-metal Preemptive Scheduler

The core of an RTOS for the ARM Cortex-M4, running on an STM32 NUCLEO-F401RE board. It uses no HAL, no vendor startup code and no libraries.

  • Hand-written linker script, interrupt vector table and reset handler that sets up .data and .bss
  • SysTick triggers PendSV, which performs a round-robin context switch in assembly
  • Tasks run on the process stack (PSP) using EXC_RETURN, and each new task starts from a hand-built fake stack frame
  • Debugged on the board with GDB and st-util

CHIP-8 Emulator

An emulator for the CHIP-8 virtual machine from the 1970s. It runs original ROMs such as Pong, with graphics, sound and keyboard input through SDL2.

  • Implements the full instruction set, validated against Timendus' CHIP-8 test suite
  • Handles the tricky VF flag edge cases, including when VF itself is an operand
  • Sprite clipping and wrapping match the original COSMAC VIP behaviour
  • The CPU (~700 Hz) and the 60 Hz timers/rendering run at separate rates, and the beep is a 440 Hz square wave generated in an audio callback
